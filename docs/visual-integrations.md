# Visual integrations

The storefront uses a custom royal boutique system, retaining the original logo, pink/gold identity and complete category/product routes. The owner explicitly requested a new layout and more organised navigation, then rejected nonuniform composition. The current direction uses one pale-rose opening canvas, wine typography, an intact full-width desktop film, an inset mobile film and shared page gutters. Category grids use four/two equal square frames; product edits use four/two equal 4:5 frames. Staggered card placement and an oversized first product are removed. The footer follows the pale surface language, and account/cart/checkout headings stay compact.

- Taste: `Leonxlnx/taste-skill`, installed locally as `design-taste-frontend`. Its editorial guidance applies to browsing and brand pages; checkout stays a clear, conventional form.
- ShaderGradient: `@shadergradient/react`, Three.js and React Three Fiber, installed with pnpm. One fixed `RoyalAtmosphere` scene connects the homepage/story page and provides real pink motion behind the translucent header. Passive pointer/touch/wheel events are coalesced to one animation frame; one tracked touch avoids multitouch jumps. A damped spring smooths displacement and preserves release inertia, while wave density/frequency stay fixed. Parent-held dynamics survive hidden/offscreen/route canvas unmounts, including paused restoration. The grain-free palette uses rose `#fce8f1`/`#dc91b7` with restrained gold `#f1dba8`. Shared Pause motion switches the scene to a demand frame loop and freezes the film. Shopping pages disable shader rendering and use opaque content. Photographs retain their colours. CSS remains available while loading, if WebGL fails, or with reduced motion/transparency. Physical touch, Safari and performance results are not claimed.
- Liquid Glass JS: the MIT rounded-rectangle distance and edge/rim equations from `dashersw/liquid-glass-js` are retained as an optional adaptation in `glass-edge.frag`. The single-row header uses native controls, translucent rose material, backdrop blur, specular edge reflections and a passive pointer/touch sheen. It blurs the shared background without a separate header canvas. Opaque fallback and reduced-transparency/motion paths retain legibility. The storefront does not capture page or customer contents.
- Brand marks: the original script wordmark remains in the header. The owner-supplied 2000x2000 crest at `/brand-emblem.png` is displayed intact on the story page and as a compact square footer seal, with lazy image loading and one subtle entrance that is disabled for reduced motion. Its colours, proportions and artwork are unchanged; it is not cropped or combined with the old wordmark.
- Liquid Logo: the MIT shader from `collidingScopes/liquid-logo` is retained as an optional source integration but is inactive in the current footer. It does not render over the new crest. MIT attribution remains in `licenses/`.
- Navigation inspiration: [Navbar Gallery](https://www.navbar.gallery/), particularly compact single-row chrome, a grouped mega menu and full-screen mobile navigation. The header has one Collections trigger, a six-group keyboard-operable tab rail, organised subcategory columns and actual product photography. Mobile uses accordions with a persistent close bar. The original mobile logo stays at the viewport centre independently of the utility widths, with a smaller narrow-phone mark to avoid overlap.
- Motion reference: [Zajno motion principles](https://motion.zajno.com/), reviewed in the browser. Masked word entrances, calibrated easing and bounded image reveals guide attention while the photographic grid remains aligned. Its identity and source code are not copied.
- Art direction reference: [Basement Studio showcase](https://basement.studio/showcase#list). Borrow deliberate scale, interactive polish and compositional restraint rather than its black studio identity.

These graphics projects are code dependencies or vendored shader adaptations, not ChatGPT account plugins. Taste is a local Codex skill; no claim is made that it was installed into cloud ChatGPT. MIT notices for adapted code are in `licenses/`.

Performance: ShaderGradient is isolated in a dynamic chunk. Its compressed size must be accounted for in launch performance checks. Effects are ornamental, never gate a purchase action, and do not alter product photographs.

The swish driver uses the installed package's `shadergradient-mesh` name and `material.userData` uniforms. Keep this interaction isolated and run regression checks when upgrading ShaderGradient; these implementation details are not a stable public interaction contract. Input stays outside React state, so pointer movement does not rerender the interface per frame. No pointer capture or default-prevention is used for the decorative surface.

## Scroll-driven jewellery motion

The Necklace Story now uses a custom art-directed film generated through the owner-authorised Google Flow workspace using Omni 1.1 Flash, 16:9, eight seconds, 1280x720. It depicts imagined ornamental jewellery, identified in the visible caption, not a purchasable SKU. The first procedural 3D necklace has been replaced. Original catalogue photography remains unchanged. No media or account credentials were embedded in the source. The signed temporary media URL was downloaded through the browser and is not a runtime dependency.

GSAP ScrollTrigger pins only the cinema, caption and controls below the measured header for 0.9 viewport of native scrolling. Film progress completes by 84% of that interval and holds briefly before release. Latest-target seeks are RAF-coalesced with no delayed scrub tween; reverse scrolling reverses the film. The title stays above in ordinary flow. The intact 16:9 frame scales to the available height, with caption/control measurements included; mobile keeps shared gutters. Pause retains the actual frame across media remounts and resumes at current scroll progress. The 5.5-second muted MP4 has keyframes every twelve frames and fast-start metadata. A poster remains available before decoding, on error, or with reduced motion; reduced motion removes the pin entirely. Native collection anchors skip the pin and initial deep links account for its spacer. There is no tall 240svh hero, changing chapter copy or separate dark campaign frame.

At the owner's explicit request, the Gemini sparkle at x1124/y562 in a 76px square of empty background was removed with FFmpeg's contextual `delogo` interpolation. The product silhouette and framing were not modified. The poster was regenerated from the cleaned film. Before/after frames were inspected, and the untouched generation master stays outside the public repository.

The browser offered a 1080p upscale; its export was requested but had not been retrieved at this verification point. No 1080p or 4K claim is made for the committed 720p film. The final media payload and real-device decode/seeking must be measured at launch.

The references supplied by the owner were reviewed:

- [HorizonX ARQ-01](https://horizonx.so/explore/arq-01-carry-the-horizon): chapter-based product storytelling and scroll-controlled composition. Its paid code/image sequence was not copied.
- [Lapa Ninja ecommerce motion](https://www.lapa.ninja/motion/ecommerce/): product-focused reveal/transition patterns. The gallery was inspected through the browser because web text retrieval was unavailable; several embedded videos reported playback errors.
- [21st.dev](https://21st.dev/): glass and WebGL component composition. The implementation is custom source, without adopting an unrelated template or purchasing a component.
- [GSAP ScrollTrigger documentation](https://gsap.com/docs/v3/Plugins/ScrollTrigger/): scrub, media-query cleanup and viewport-triggered reveals.

Motion preferences have runtime fallbacks. Without motion, the pin is disabled and the poster/useful static copy remain visible. Media errors retain the poster; the skip link stays available. Small-height windows scale the complete frame to fit with its caption and controls. Checkout, account forms and order verification retain their conventional behaviour. No physical-touch, mobile Safari or Core Web Vitals pass is implied; those require verification on the actual deployment and devices.
